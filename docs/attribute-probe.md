# 토지 속성 API 개발 진단

## 실행

기존 Vite 개발 서버가 실행 중일 때 Edge에서
`http://127.0.0.1:5173/IMJINHONG/__dev/attributes`를 연다.
유효한 공개 필지의 19자리 PNU와 원하는 공시지가 연도를 입력하고 서비스별 진단 버튼을 누른다.
지도는 생성하지 않으며 BOX·POINT·배경지도 요청도 시작하지 않는다.

## 현재 지원 상태

공식 문서의 다른 읽기 경로에서 두 서비스의 JSONP 샘플을 확보했다.
두 버튼은 입력·설정을 검사한 뒤 기존 키/domain과 sandbox를 사용해 해당 API에 **전송을 1회 시도**한다.
실제 API 인증·응답 성공은 아직 미검증이다. 자동 실행·자동 재시도·추가 페이지 조회는 없다.
서비스별 진행 중 중복 요청은 차단하고 결과를 독립적으로 표시한다.
일반 지도 상세 패널은 개발 진단 모듈을 import하지 않는다. 지도용 서비스 로더가 같은 sandbox와 기존 파서를 사용해 POINT 선택 후 조회한다.

토지임야 파라미터: `pnu`, `key`, `domain`, `format=json`, `numOfRows=10`, `pageNo=1`.
공시지가에는 사용자 지정 `stdrYear`만 추가한다. PNU는 19자리 문자열로 보존한다.

공식 확인 대상:
- https://www.vworld.kr/dtna/dtna_apiSvcFc_s001.do?apiNum=128
- https://www.vworld.kr/dtna/dtna_apiSvcFc_s001.do?apiNum=25
- 공식 JSONP 샘플: 위 사이트의 `/dtna/dtna_sampleCode_a003.do?gubun=JSONP&apiNum=128` 및 `apiNum=25`.
  공식 샘플의 jQuery JSONP 기본 callback 규칙을 공통 전송기로 구현하며 요청주소는 공식 명세의 HTTPS를 사용한다.

## 전송 구조

`sandboxJsonp.ts`는 고정된 서비스 식별자에 대해서만 다음 경로를 허용한다.
- cadastral: `/req/data`
- ledger: `/ned/data/ladfrlList`
- price: `/ned/data/getIndvdLandPriceAttr`

이 목록 이외의 임의 URL은 허용하지 않는다.
기존 지적 요청은 기존 함수 이름과 파라미터로 공통 함수를 호출한다.
iframe sandbox 권한, 요청별 콜백, source/origin/ID 검사, 타임아웃과 자원 정리를 유지한다.
속성 진단 함수는 서비스별 파라미터를 독립적으로 구성한다.
`/req/data`의 service·geomFilter·size 파라미터를 속성 API에 그대로 전달하지 않는다.

## 출력과 제한

차단 시 HTTP·API 응답·건수·PNU 일치·기준일은 미확인으로 표시한다.
응답 요약은 기존 파서를 재사용하고 허용된 필드명과 속성만 반환한다.
임의 필드명, 서버 오류 원문, 인증키, 인증 URL, 원본 응답은 출력하지 않는다.
일반 스크립트 요청의 HTTP 상태는 이 전송기로 직접 확인할 수 없으므로 미확인으로 표시한다.
전송 시도는 HTTP 송신 횟수의 증거가 아니다. 콜백 수신 후 PNU·연도·자료형 검증을 통과해야 성공으로 표시한다.
인증 오류(`ATTRIBUTE_AUTH`), 일반 API 오류(`ATTRIBUTE_API`), 응답 검증 오류(`ATTRIBUTE_RESPONSE_INVALID`),
전송 오류(`ATTRIBUTE_TRANSPORT`), 시간 초과(`ATTRIBUTE_TIMEOUT`)를 구분하며 미확인 서버 코드는 숨긴다.
화면 해제 시 AbortSignal로 결과를 무효화하고 iframe과 리스너를 정리한다. 네트워크 취소는 보장하지 않는다.
공시지가 연도는 사용자 입력값이며 최신 가용 연도라고 표시하지 않는다.

개발 페이지는 Vite serve 전용 middleware로만 제공하고 main.ts에서 import하지 않는다.
프로덕션 빌드에 진단 UI를 포함하지 않는다. 지도 속성 조회는 개발 진단 UI와 독립된 서비스 코드에서 동작한다.

검증: `node --test tests/parcel-offline.test.mjs tests/attribute-probe-offline.test.mjs`
이는 모의 통신·DOM 검증이며 실제 V-World 인증·CSP 실행·API 응답을 증명하지 않는다.

## 공시지가 응답 실패 단계 추적

`ATTRIBUTE_RESPONSE_INVALID`에는 공시지가 전용 실패 단계를 추가했다.
`envelope`는 최상위 봉투, `rows`는 목록 구조, `pnu`는 식별자 형식/일치,
`year`는 문자열 기준연도 일치, `month`는 두 자리 월,
`price`는 비음수 가격 형식, `published-date`/`updated-date`는 날짜 형식,
`page`는 건수·페이지 모순이다. 서로 다른 여러 기준월/값은 정상 레코드 목록으로 표시한다.
`api`는 API가 반환한 오류이며 정상 0건과 구분한다.

실패해도 기대 봉투·field의 타입과 배열 길이, 허용된 필드의 자료형/날짜 형식,
유효한 건수 메타데이터만 요약한다. 임의 필드명·PNU 값·인증정보·원본 응답은 표시하지 않는다.
요약 탐색 상한 도달 시 이를 표시한다. 구조를 추정하여 성공 처리하거나 월/날짜를 임의 보정하지 않는다.
공식 문서의 날짜 예시는 YYYY-MM-DD지만 실제 실패 응답의 자료형·구조는 아직 미확인이다.

동일 PNU와 2025년으로 개별공시지가 버튼만 한 번 실행한 뒤 실패 단계와 구조 요약을 확인한다.
토지임야 버튼과 지도는 이번 진단에 사용할 필요가 없다. 자동 재시도·추가 페이지는 없다.

## 복수 공시지가 레코드

실제 사용자 진단에서 `indvdLandPrices.field` 배열 2건이 확인되어 단일 레코드 가정을 제거했다.
`parseLandPrice`는 레코드 목록과 원본 반환 건수·전체 건수·페이지 크기/번호·완전성·중복 제거 건수를 반환한다.
각 행은 PNU·요청 연도·월·가격·날짜 검사를 모두 통과해야 한다. 다른 기준월/공시일/가격/갱신일은 합치지 않는다.
원본 행의 모든 자체 필드와 자료형/값이 일치하는 완전 중복만 제거한다. 알려지지 않은 속성 차이도 보수적으로 보존한다.
원본 응답이나 추가 속성은 결과에 저장하지 않으며 PNU 값은 개발 요약에 출력하지 않는다.

페이지 완전성은 중복 제거 전 반환 건수로 판단한다.
- 전체 건수가 현재 반환 건수보다 크면 부분 조회로 안내한다. 추가 페이지는 요청하지 않는다.
- 전체 건수·페이지 크기·페이지 번호가 일치해야 API 메타데이터 기준 완전 조회로 표시한다.
- 메타데이터가 빠지면 완전성 미확인이다. 모순되는 메타데이터는 오류다.
- 정상 totalCount=0은 자료 없음이다.

진단 화면에서 각 행의 기준연월·원/㎡ 가격·공시일·갱신일을 응답 순서대로 표시한다.
최신 행을 자동 선택하지 않는다. 지도 상세 패널에서도 POINT 선택 후 같은 복수 레코드 검증을 적용한다.
같은 PNU `1174010800104440003`와 `2025`년으로 공시지가 버튼만 한 번 재검증한다.
이번 변경 자체에서는 실제 API를 호출하지 않았다.

## 기준연도 생략 조회

개발 화면의 **기준연도 생략 조회 (1회)** 버튼은 연도 입력값과 관계없이 `stdrYear`를 요청에서 제외한다.
지정연도 진단 버튼은 기존처럼 네 자리 연도 입력을 요구한다. 빈 문자열을 자동으로 생략 모드로 바꾸지 않는다.
두 버튼은 동일 서비스의 중복 진행 방지를 공유하며, 각각 사용자가 누른 경우에만 선택한 페이지를 1회 요청한다.
`numOfRows=10`, 기존 키/domain 및 sandbox는 유지한다. 기본 페이지는 1이며 생략 조회만 명시적으로 2를 선택할 수 있다.
개발 진단의 지정연도 조회는 그대로 유지한다. 지도 패널은 별도 이력 수집기를 사용해 연도 생략 결과의 필요한 페이지를 조회한다.

생략 응답은 각 행의 실제 `stdrYear`가 네 자리 문자열인지 검증하고 그 값을 표시한다.
PNU·월·가격·날짜·완전 중복 처리와 상이한 갱신일 레코드 보존은 지정 조회와 같다.
실제 반환 연도 목록, 각 레코드의 기준연월·가격·공시일·갱신일과 페이지 메타데이터를 표시한다.
페이지 완전성은 해당 조회 조건의 API 응답 기준이다. 페이지가 완전해도 전체 과거 이력이 제공된다고 단정하지 않는다.
부분 조회·완전성 미확인은 별도로 안내하고 자동 추가 페이지/연도 조회는 하지 않는다.
개발 진단에서는 증감률 계산이나 대표값 선택을 하지 않는다. 지도 이력 패널은 전체 페이지 검증 후 조건이 맞을 때 증감률을 계산한다.

Edge에서 개발 진단 주소를 새로고침하고 유효한 공개 필지 PNU를 입력한 뒤 생략 조회 버튼만 한 번 누른다.
반환 연도 목록·레코드·전체/반환 건수·페이지 크기/번호·페이지 완전성을 확인한다.
API 키·전체 요청 URL·원본 응답은 공유하지 않는다. 실패하면 반복 클릭하지 않는다.

### 기준연도 생략 2페이지 검증

생략 조회 페이지 선택에서 **2페이지**를 고른 뒤 생략 조회 버튼을 한 번 누른다.
요청에는 `pageNo=2`, `numOfRows=10`이 포함되고 `stdrYear`는 포함되지 않는다.
응답 페이지 번호는 요청 번호와 일치해야 한다. 전체 건수가 있으면 페이지 오프셋을 고려해 반환 가능한 건수 상한을 확인한다.
기대 예시는 전체 13건 중 2페이지 최대 3건이며, 이는 실제 2페이지 응답을 관측한 결과가 아니다.
페이지 1 결과와 합산·병합하지 않는다. 마지막 페이지 수신만으로 전체 이력 완전 수집을 주장하지 않는다.
확인할 항목은 요청 페이지·응답 페이지·전체 건수·현재 반환 건수·반환 연도와 각 행의 기준월/가격/공시일/갱신일이다.
같은 PNU `1120011300105280006`로 **2페이지를 한 번만** 조회한다. 지정연도 진단·토지임야는 기본 1페이지를 유지하며 지도 이력 수집과 독립적이다.
